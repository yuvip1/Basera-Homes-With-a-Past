# BUG-2026-007: Next.js build fails on `/_not-found` page using `useRouter`

- **Status:** Fixed
- **Severity / priority:** Medium / P2
- **Phase / feature:** Phase 2 — Frontend build
- **Environment and version/commit:** Next.js 16.0.0, React 18.3.0, pnpm 12.16.1
- **First observed:** 2026-11-04
- **Fixed / verified:** 2026-11-04 22:00 IST

## Expected behavior
`pnpm --filter frontend run build` completes successfully.

## Actual behavior
```
Error occurred prerendering page "/_not-found". Read more: https://nextjs.org/docs/messages/prerender-error
Error: NextRouter was not mounted. https://nextjs.org/docs/messages/next-router-not-mounted
    at q (C:\Users\yuvra\Desktop\Basera-Homes with a Past\frontend\.next\server\chunks\ssr\[root-of-the-server]__93eb0517._.js:23:125)
```

## Reproduction steps
1. `cd C:\Users\yuvra\Desktop\Basera-Homes with a Past\frontend`
2. `pnpm build`
3. Observe build failure on `/_not-found` page

## Evidence
- Error output from `pnpm build`:
  ```
  Error: NextRouter was not mounted. https://nextjs.org/docs/messages/next-router-not-mounted
  ```

## Root-cause analysis
- **Confirmed facts**: 
  - The `/_not-found` page (Next.js special route) was using `useRouter` from `next/navigation`
  - During static generation (`next build`), `useRouter` is not available because there's no router context during static generation
  - The `_not-found` page is statically generated by default in Next.js App Router

- **Root cause status**: Confirmed

## Fix
- Removed `useRouter` import and usage from `not-found.tsx`
- Replaced `useRouter().push('/')` with a standard `<a href="/">` link
- Removed `useRouter` import from `next/navigation`

## Files changed
- `frontend/src/app/not-found.tsx` — Removed `useRouter` import and usage

## Prevention / lessons learned
- Next.js App Router special pages (`_not-found`, `loading`, `error`) are statically generated by default
- These pages cannot use client-side hooks like `useRouter`, `useSearchParams`, etc.
- Use `export const dynamic = 'force-dynamic'` if dynamic behavior is needed, or use static HTML/links
